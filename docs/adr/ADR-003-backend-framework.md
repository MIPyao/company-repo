# ADR-003: 后端框架选型

日期: 2026-05-09
状态: 已采纳
作者: CTO (a83dcf07-81be-46b5-863d-e6b31207a2b2)

## 上下文

MIPYAO需要选择后端框架来构建API和服务。作为zero person company，我们需要：
- 快速开发RESTful API
- 与前端TypeScript/Node.js技术栈统一
- 良好的性能和开发体验
- 易于部署和维护
- 对AI辅助开发友好

候选方案：
1. **Express.js** - 最流行的Node.js框架，生态丰富但较底层
2. **Fastify** - 高性能，内置JSON Schema验证，现代化
3. **NestJS** - 类Angular架构，功能完整但学习曲线陡
4. **Hono** - 超轻量，支持多种运行时，适合边缘计算
5. **tRPC** - 类型安全API，与前端共享类型

## 决策

选择 **Fastify** 作为主后端框架，并考虑 **tRPC** 用于需要类型安全的场景。

### 技术选型细节

| 项目 | 选择 | 理由 |
|------|------|------|
| 主框架 | Fastify | 高性能，插件架构，内置验证，JSON Schema支持 |
| API风格 | RESTful API | 主流标准，易于理解和调试 |
| 备选方案 | tRPC | 当前后端共享类型，减少前后端契约维护 |
| 验证 | Fastify内置 + Zod | 类型安全的请求验证 |
| 认证 | JWT + bcrypt | 无状态认证，安全可靠 |
| ORM | Prisma | TypeScript优先，迁移管理方便 |
| 数据库 | PostgreSQL | 功能强大，开源免费 |

### 为什么不选Express.js？
- 需要手动添加很多中间件
- 没有内置验证和序列化
- Fastify性能更好，开发体验更现代

### 为什么不选NestJS？
- 架构过重，学习曲线陡
- 对于小团队来说可能过度设计
- Fastify更轻量灵活

### 为什么考虑tRPC？
- 前后端共享TypeScript类型
- 消除API契约维护成本
- 但需要评估是否适合所有场景

## 后果

### 积极影响
1. **性能优秀** - Fastify是Node.js最快的web框架之一
2. **开发体验好** - 插件架构清晰，内置验证和序列化
3. **类型安全** - 结合Prisma和Zod，端到端类型安全
4. **易于测试** - Fastify的注入测试很方便
5. **AI辅助友好** - Fastify文档完善，AI训练数据充足

### 潜在风险
1. **生态相对Express较小** - 某些中间件可能需要自己找替代品
2. **tRPC学习成本** - 需要理解其工作原理和适用场景

### 缓解措施
- 优先使用Fastify官方插件
- 建立内部插件库封装常用功能
- 为tRPC创建示例代码和文档

## 合规说明

本决策符合MIPYAO公司的以下原则：
- ✅ **AI-first战略** - TypeScript全栈，类型安全，AI辅助开发效果好
- ✅ **低成本** - 开源框架，无授权费用
- ✅ **高效率** - 快速开发API，减少样板代码
- ✅ **可扩展** - 插件架构，易于添加新功能
